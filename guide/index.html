Text Search Engine · MIT

JavaScript 拼音模糊搜索：接入与选型

Text Search Engine 是一个 JavaScript / TypeScript npm 库，适合在浏览器或 Node.js 搜索一组本地字符串或对象。一个查询可以混合汉字、全拼、拼音首字母和英文；命中范围可直接用来高亮原文。

安装与快速开始

npm i text-search-engine

以下示例在 npm 发布的 1.6.2 上验证，API 自 1.6.0 起可用。用 Node.js 运行时将示例保存为 .mjs。示例不调用 React；但 1.6.2 声明了 React 16.8、17 或 18 的 peer dependency，npm 可能自动安装 React 18，已有 React 19 的项目可能遇到安装冲突。

1. 用拼音首字母搜索数组

import { searchItems } from 'text-search-engine'

const [hit] = searchItems(['React', '监控平台'], 'jk')
console.log(hit.item, hit.hitRanges)
// 监控平台, [[0, 1]]

2. 同时匹配标题与域名

import { createSearcher } from 'text-search-engine'

const pages = [{ title: 'React 监控平台', host: 'github.com' }]
const searcher = createSearcher(pages, {
  getFields: ({ title, host }) => ({ title, host }),
})
const [hit] = searcher.search('jk github')
console.log(hit.fieldHitRanges)
// { title: [[6, 7]], host: [[0, 5]] }

3. 从原文取出高亮片段

接着运行上例。区间是 UTF-16 下标，结束位置也包含在内，所以传给 slice 时加 1。浏览器中可用 textContent 填充 <mark>，不要把原始字符串拼成 HTML。

const [start, end] = hit.fieldHitRanges.title[0]
console.log(hit.item.title.slice(start, end + 1))
// 监控

每次输入变化，复用同一个 createSearcher；列表、字段值或选项变了再重建。字段需转成字符串；区间针对转换后的精确字符串。空查询返回 []，要展示全量列表，请在调用侧处理。默认维持输入顺序；业务需要相关性排序时，在 sort 中明确规则。

怎么选：Text Search Engine、pinyin-pro 还是 Fuse.js？

  • Text Search Engine：已经有一组本地列表，想让拼音、英文、对象字段及原文高亮一起工作。它不是全文索引，也不是通用拼写纠错库。
  • pinyin-pro match：主要做单条字符串匹配或拼音转换，想自己管列表遍历和排序。match() 会返回匹配下标；原文高亮并非本库独有。
  • Fuse.js + Pinyin：更看重英文拼写误差与字段权重时，先试 Fuse.js。要把中文转成全拼和首字母，需要预处理；若要高亮原文字，还要把拼音字段下标映射回原文。

用同一组数据实测

小型对照，不是全局排名。8 个查询覆盖首字母、跨字段、多音字、漏字母、换位和无匹配；耗时样本把这 7 条对象扩成 1,000 条带数字后缀的记录。首次包含构造和首个 jk 查询；重复查询复用同一搜索器，以 24 次混合查询的平均耗时作为每轮样本。表中为 31 轮中位数（丢弃前 2 轮），不含渲染、模块加载或高亮区间归一化。
